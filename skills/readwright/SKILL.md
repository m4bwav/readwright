# readwright

A novel is 150,000 to 300,000 tokens. Dumping it with a converter (`epr -d`, `pandoc -t plain`, `ebook-convert book.txt`) fills the context before the question is answered. readwright gives the agent a table of contents with word counts, then the chosen sections, then search results with section and paragraph numbers, so it reads what the task needs and nothing else.

`RW` below means `python "<this folder>/scripts/rw.py"` (`python3` on macOS and Linux). The launchers `scripts/rw.sh` and `scripts/rw.ps1` do the same. It needs Python 3.10 or newer and nothing else for the built-in formats; `RW formats` shows which external tools this machine has.

## Step 0: freshness

Read [evergreen.json](evergreen.json). If `contradiction` is set or today is on or after `next_due`, say so in one line, do the task, then refresh (MAINTENANCE.md). Converter versions and ebook formats change; the procedure below does not depend on them.

Discord: a live channel is not a file; read it with everscout's `scripts/es_discord.py` (the user's own invited bot, everscout `kb/discord.md`). A channel export the user made (JSON or HTML) reads like any JSON or HTML file here.

## Step 1: size it up

Run `RW info FILE`. It prints the detected format (from the file's bytes, not its extension), title, author, language, section count, words and approximate tokens (characters divided by 4). Under about 6,000 tokens (25,000 characters), `RW read FILE` prints the whole text and you can stop here.

If info reports DRM, say so plainly and stop. readwright never removes DRM, and neither should you: suggest the store's own reader or a DRM-free copy from the seller. If it names a missing tool (pdftotext, calibre's ebook-convert, LibreOffice), pass on the install line it prints. Never install anything without the user's yes. For a PDF, the agent's own Read tool with page ranges is often the better route.

If info prints `note: no text layer`, the book is page images (a scan) and readwright has nothing to read. Take the routes the note names, in its order. First, a copy of the same book in another format beside it; a DjVu copy often carries OCR text. Then, for a PDF, `RW ocr FILE`: it renders the pages and runs the OCR built into Windows 10 and 11 (or tesseract where installed), about a second a page, saving after every 25 pages, and keeps the text in `~/.readwright/ocr/` so `info`, `toc`, `read` and `grep` on the same file use it from then on (`--pages N-M` for a few pages, `--force` to redo). Run a whole book in the background. OCR misreads some letters and has no headings, so sections are pages; check a quote against a page image. Last, a few pages rendered with `RW page FILE 1-5` (60 dpi, `--dpi`, `--out-dir`) and viewed with your own image reader. Ask before installing an OCR tool.

## Step 2: outline

Run `RW toc FILE`. Each line is `N. title (words w)`, indented by level; `--ids` adds each section's id (file and fragment, page, sheet), which you rarely need. EPUB titles come from the book's own navigation (nav document or NCX), DOCX and ODT titles from heading styles, HTML from h1 to h3, plain text and Markdown from headings or CHAPTER lines. Text with no structure is cut into parts of about 3,000 words. For a zip archive, toc lists the members; add `--member NAME` (or its number) to every later command.

Books that list each chapter number as its own near-empty section (Packt, some O'Reilly) are shown merged: `Ch. 12: Title`, printed under the title's section number (the number-only section is hidden but keeps its number and can still be read). `RW toc FILE --depth 1` prints only the top level (parts and chapters) with each line's words rolled up from the sections below it (`--depth 2` adds the next level; JSON gets `chapter` and `words_total`). Use it to count chapters instead of counting by hand. A PDF with no outline lists one section per page; `RW toc FILE --group` folds pages that share a running head into page ranges (chapters) to read with `--section 20-40`; with no running heads it uses the printed contents page, where each entry is a title line then a page-number line (0.26.0), or entries run on as `Title ... 21 Next ... 26` (0.35.0), and `toc` says so in a note.

Match the user's words to toc lines. "Chapter 14" usually means the line titled CHAPTER FOURTEEN, which in many ebooks holds only the chapter title and an epigraph: its body is the next section. The word counts show this (72 words, then 6,330). Section numbers are not chapter numbers: front matter comes first, so chapter 16 of a novel may be section 24.

## Step 3: read only what is needed

- `RW read FILE --section 43-44` (also `N`, `N-`, `N,M`; a repeated `--section` adds up) or `--title "REGEX"` (case-insensitive, matched against titles and ids; when nothing matches, spaces are ignored, so `westgate` finds WEST GATE).
- When `--title` lands on a section under 300 words, the section after it is added and a note says so. `--with-next` does the same for any selection.
- A section whose title repeats 3 or more times in the book ("Getting ready", "How to do it...", "There's more...") is shown with the nearest distinctive heading before it, in `read` headers and in `toc`: `How to do it... (in: Following a path)` (`in` in toc JSON).
- `--max-words N` caps each selected section at N words, so a batch like `--section 27-58 --max-words 80` stays small; a cut section ends `[cut at N of M words; continue with --section S --offset C]`.
- `--drop-repeated` (read) drops short paragraphs (40 words or fewer) that recur in 30% or more of the sections, verbatim or with the same last four words once digits are folded: per-image credits and copyright notices in EPUBs. It also drops a line of eight words or fewer repeated ten times or more inside one section (a quarter of its paragraphs), such as the "GO TO NOTE REFERENCE IN TEXT" back-link after every endnote. Off by default.
- `--skip-code` (read and grep) drops code blocks found by structure (EPUB and HTML `<pre>`, fenced Markdown; PDFs have no marker, so not there) and says how many words went. Advice lines come as one line at the end; `--quiet` drops them.
- `--lang CODE` (read and grep, 0.43.0; en, de, es, fr, it, nl, pt) keeps the paragraphs whose short common words favour that language, for an edition printing several side by side. Ties and fragments under 4 words go, except headings; code and tables stay; words glued by OCR still count. The footer says how many went, and `--max-chars` counts what is left. `info` notes a book with many paragraphs in two or more languages.
- `--headings` (read, 0.20.0) prints only the heading paragraphs of the chosen sections, indented by level, each with its paragraph number and the words under it; jump with `--at-para P`. A section with no headings (a PDF without structure) says so: use `toc --group` or grep.
- `--strip-boilerplate` (read and grep) drops lines repeated across a PDF's pages: footers, bare page numbers, running headers, found by how often they repeat. Use it on both commands so grep's paragraph numbers match `--at-para`.
- Every section starts with a header line: `=== [43/80] title | id ... | words | starts at word N of TOTAL (P%) ===`.
- Output stops at `--max-chars` (default 25,000). The cut ends at a paragraph, line or sentence break near the limit (0.11.1), and the last line then says where to continue: `--offset N`. Keep each read under your shell tool's output limit: Claude Code shows 30,000 characters of a command's output and saves the rest to a file you would then have to open. For two long chapters, read them one call each. For more than that, write the selection with `--out <scratch>/part.txt` and open it with your own Read tool. To hand a reader agent several chapters, `--out-dir <scratch>/secs` writes each selected section to its own file (`NNN-title.txt`) and lists their sizes (0.12.0).
- `--section` takes a list and ranges in one call: `--section 61,80,87` or `--section 12,189-190`. Sections print in that order, each with its own header.
- A short selection ends with a hint naming the next section when that section probably carries on the text: the selection is a title page or epigraph (under 60 words), or the next section is untitled, marked continued, or repeats the title (0.15.0; it no longer fires on every small subsection).
- `read` without a selector refuses when the text is over the limit (exit code 2) and prints the toc instead. That refusal is the tool working: pick sections.
- `--format md` keeps headings and lists as Markdown; `--out FILE` writes the selection to a file; with `--max-chars` it cuts at a clean break and prints `cut at chars A-B of N; write the rest with --offset B` (0.15.1). `--compact` drops the blank line between paragraphs (0.13.0); give it again with `--offset`.

## Step 4: search

`RW grep FILE "PATTERN" -C 1 --max 5` prints each matching paragraph with its section number and title, paragraph number and one paragraph of context on each side. Long paragraphs are trimmed around the match (`--width`). `--after N` (`-A N`) adds N paragraphs after each hit, shown up to `--width` with their line breaks: the code block or list that follows the sentence naming it (0.15.0). A pattern with no capital letter matches any case (`--case-sensitive` forces exact case, `-i` forces any case), and `-F` takes a plain string; `--count` gives matches per section, the quickest way to find where a character or term appears. Each hit line ends `| offset N`, the character offset `read --section S --offset N` starts at; `read --section S --at-para P` starts at a paragraph. Use them when toc notes one giant section (bookmarks that stop early); since 0.17.0 such a section is first cut at the chapters a printed contents page or a "Chapter N, Title" list names, so the note shows only when that fails. Exit code 1 means no match. Search before reading when the user asks where or whether something is mentioned.

`RW rank FILE topic words` (0.24.0) ranks sections by BM25 for a few topic words and prints score, words and the terms each holds: which section to read first, where grep prints hits in book order. Stop words and plural, -ed and -ing endings are folded, so `shingles` finds `shingling`; a word not in the book is named. `--paras` ranks paragraphs (heading lines often win: read from there), `--top N`, `--section`, `--k1` and `--b` as in BM25. Rank first on a long book, then grep inside the top sections.

## Step 5: whole book to a scratch file

For work that needs many passes over a long book (every scene with a character, a timeline), run `RW dump FILE --out <scratch>/book.txt` once. Then use your own search and read tools on that file, never `cat`. Section markers are lines starting `=== [N/`; `--format md` writes `<!-- readwright section N/... -->` comments with Markdown headings. Dump writes to stdout only when the text is under 25,000 characters. Put the file in the session's scratch or temp folder, never in the user's repository.

## Step 6: answer

Quote briefly. For a copyrighted book, summarise and quote a sentence or two at a time, never whole pages or chapters, even when the user owns the copy. Cite where each point came from (section number and title) so the user can check it. When a conversion note was printed (calibre, LibreOffice, pdftotext), mention that the text came through a converter if the wording matters.

## Distilling a book

- Building on an earlier read's notes: grep two or three of the passages they cite before reusing them, and read one chapter the notes skipped, so the new write-up adds something and carries no copied slip.
- Look up a study the author cites for a strong claim, and record its limits. A popular book can drop them: one reported a sex difference without saying the paper found it only in part of its age range.

A broad reference already read for another subject: check what the earlier notes aimed at your subject, then read the chapters on your own job they skipped (an evaluation appendix, the analysis chapters), split by kind across two reader agents.

A flat PDF section with numbered or whole-caps headings: `read --headings` lists them, then `--at-para` jumps to the one you want.

An edited handbook: read the editor's introduction first, since it says which chapter covers what, then only those chapters' openings and any passage on method. Each chapter has its own authors, so cite the chapter and judge it alone.

A how-to from a neighbouring trade (theatre sound read for game effects): skip the people and the venue hardware, read the chapters on making the material, and grep the job's words across the rest. Text like `mu?ed` can be in the publisher's file; check the source before blaming the reader.

A long history survey: skip the instrument chapters. Grep the method words, read the chapters on those, the conclusion, and any passage where the author judges a claim. Dates in such books can differ from other sources by a year, so check one before repeating it.

Reference books organised by device or parameter: grep your own subject's words first (`\bwind\b`, not `wind`, which also hits Windows); the few passages naming it show which sections to read. Then check any worked number yourself: a stated limit or distance can be off even when the rest is sound.

Synthesizer or software textbooks with worked patches: the settings belong to the bundled product, so read each patch's opening paragraphs for the reasoning and skip the slider steps. `--from` and `--until` can cut them.

Interview-led journalism: the methods sit inside the quotes and most of each chapter describes albums or works. Grep the craft words, read those hits with `--at-para`, and cite each method as that person's report.

A recipe book built on patch diagrams (Pure Data, Max): object names in boxes vanish from the text and leave holes ("use the and objects"), square roots and superscripts flatten (`x2` may be x squared), and values in figures are missing. Rebuild formulas from the physics the text names and mark them restored; mark figure-only values as such; the section after a practical's DSP part may hold its tail, so read the next section too. Parallel reader agents, one per group of chapters, keep the main context small.

Craft book from a neighbouring field (music mixing read for sound effects): take the reason behind each setting and mark its numbers as untested in your field.

A methods book in a language you will not run (R read for its measures): add `--skip-code --drop-images`, then `read --headings`; take what each measure means and where it fails, and check any stated default against the package's own docs. Its list of figures sits in the frontmatter, so `grep` hits there first.

Project-based tutorial: run `read --headings` on a chapter first, and read the opening, rules and warnings; the numbers sit between screen-by-screen steps, so `--from` a heading saves most of the chapter. Check the arithmetic in its worked examples.

- A polemic that builds a taxonomy: read the prologue and the opening of each chapter (`RW read FILE -s 8-16 --each-chars 2500`), since each names its move there and a later chapter may recap the list. Its numbers are often the author's own chosen samples, and its anecdotes single cases, so use it to name patterns, then search for studies of whether they happen and how often. Look for what complicates the claim as well as what supports it.
- A textbook with end-of-chapter summaries: read those first with `RW read FILE --title 'SUMMARY TITLE' --until 'boilerplate heading' --compact`, then only the sections they send you to. One 445-page PDF's 19 summaries, about 500 words each, covered the argument of its 182k words, once `--until` dropped the exercise list and web links closing each one (0.46.0).
- A PDF with pull quotes can set the sidebar's words into the body: a fragment of a sentence, then the same sentence whole. Check such a passage against the page before quoting it (`RW page`). The reader leaves these in, since a short line repeated in the next paragraph is nearly always a heading (L-060).
- A trade book whose endnotes have no markers in the text (keyed by page and a lead phrase): before trusting a claim, `grep` the name or phrase with `--title Notes` to reach its source.
- A book of short rules: read its summary chart and any list of maxims first, and fetch several sections in one call (`RW read FILE -s 3,12,83 --each-chars 3800 --drop-images`), one process and one cut per section. Then grep the beat's vocabulary for the rest; most rule sections repeat what a similar book gave (0.45.0).
- A practitioner book built on interviews: check how the people were chosen. When the author picked leaders already seen as good examples, the cases illustrate a claim and cannot show it causes results, so look for the cited studies and report them separately.
- A vendor or platform book: check its product facts against the live docs, and read those docs for what the book leaves out. One 2026 book sold a per-request router as pure saving; the vendor's own page says routing can lose the prompt cache.
- A section with few words across many pages in `toc`: its text is sitting in false sections after it, usually running heads. Read on through the next sections, and report the book if their titles repeat (0.44.2 drops heads set beside a page number).
- A book of prompts and model replies: add `--max-row-words 60` when replies sit in table rows (0.44.0), and judge the prose around a sample, since one run's reply proves little. A paragraph printed twice can be in the publisher's file: grep it before blaming the reader.
- A book that argues from studies: open the paper behind any number you keep. The unit is a common slip (one testing book says 201 flaky tests where the paper studied 201 commits).
- A multilingual edition: read one language with `--lang`, and check a garbled number against the page image with `RW page` before citing it (0.43.0).
- A how-to book about working with people: its worked example letters and the answers closing each chapter often hold the method, so read those as well as the argument prose (0.42.0 sets `Q /` letters apart in PDFs whose lines are whole paragraphs, and moves page-foot notes out of sentences as `[note N: text]`).
- A code-heavy technical book: read with `--skip-code`, since listings otherwise eat the character cap before later sections print (0.41.2 also drops numbered callout markers, 0.43.2 listing captions and legends). Grep for what the book should cover: a topic with a thin section and no index entry is a finding about the book. Trace a case study's note to its source; one security book joined two different 2021 incidents under one citation.
- `RW` output with odd characters such as `â` or `Ã¶` points to a decoding bug: report it, and do not clean it with sed.
- A popular nonfiction book resting on studies: follow the notes to two or three headline studies and look up what they measured. Popular books often report only the subgroup that fits, such as a study whose effect held for women only, presented without the men.
- A specimen or art book's text misses the plates, and few words a page signals that (`info`: words over pages; one type book had 89 where clean books had 220 to 420). View a few with `RW page FILE 40-42`; a PDF too big for your image reader still renders page by page. If `info` notes a scrambled text layer, treat exact wording with care and re-OCR with `RW ocr` or check the page (0.41.0).
- A designed art book in fixed-layout EPUB: lines rejoin into paragraphs (0.40.2). When one smaller type size recurs through the book, captions leave the body, marked `[caption] ` after the paragraph they interrupted, and a sentence over a page turn rejoins (0.41.0). Captions often hold the evidence, so read them too, and look at the page (`RW image`) when a claim rests on a picture. A book with no such size stays in file order. Pull quotes and sidebars set in larger type stay in the flow. Interviews and a closing summary usually hold the transferable rules; case chapters are examples.
- A book that ranks things in a list set inside a table (a one-cell box) now reads `a; b; c` in order (0.40.1). Before reporting a lost symbol such as `60 percent 25 percent`, look at the raw XHTML: this one was missing from the retail file. Recompute a printed table and compare it with the sentence under it: The Bogleheads' Guide prints $886,430 in a table and $866,078 in the text.
- A book of numbered short chapters under part openers: `read --chapter 78,81-83` selects by the printed number, since toc positions drift from it (0.40.0). Check a how-to book's browser or tool support claims against current docs: its advice can be dated on the day it is printed.
- A book whose tables and formulas are pictures (`[image omitted: 00028.jpg]`): `RW image FILE 00028.jpg --out-dir DIR`, then look at the file, before citing the numbers (0.38.0). Redo worked arithmetic from the printed inputs: The Little Book of Valuation prints 749/1.1021^5 as 457 where the inputs give about 461.
- A scholarly book with one notes file per chapter: `rank FILE words --body` leaves out the notes and bibliography, whose files repeat chapter titles and crowd the top (0.37.0). A history can be useful for its method and wrong in its model: read the appendices on definitions and data, look for specialists' reviews before trusting a grand pattern, and test large figures by converting them (a money supply at the exchange rate of the day exposed a wrong one in The Great Wave).
- A course-style book closes each chapter with a summary: `RW read FILE --title . --from "Key takeaways" --each-chars 1500` prints only those, so you can choose chapters from them (0.36.0). Such a book can contradict itself between chapter and example (one gives 1.3 to 1.6 and later 1.3 to 1.7), and a figure with no basis stated can mislead: its 8 letters per English word matches a count of distinct words, not running text (4.79). Check which count a number uses.
- An older web or software book: check its code-level advice against current docs before it reaches a skill; the principles last better than the markup (Web Form Design, 2008, advises `tabindex` for tab order, and MDN now warns against positive values). Look for the author's later study of a claim too (0.35.1).
- An OCR scan with figures or music examples: `--min-para-words 12` removes label and notation debris, and `--section p264-p272` reads printed pages (every sub-heading on them since 0.49.0). Check captions separately, since short ones go too.
- A workbook-style textbook: `RW toc FILE --hide "exercises|track \d+"` drops exercise and audio-track lines and keeps the section numbers (0.48.2). Keep its facts, and test its feeling-words against other sources before they reach a skill (Hewitt, Music Theory for Computer Musicians).
- A handbook often ends with its own list of guidelines and page numbers: read that first and choose pages from it (Web Typography, p. 294-300). Recompute any worked figure and open a cited study; that book printed 1.1375rem for 1.375rem (0.35.0).
- A popular book with few work examples: `rank` with the beat's words, then `grep` for offsets and read 1-3k characters at each (`--offset`), rather than whole chapters; 7k of 105k words was enough for one (0.33.0). Say which claims you could not check beyond the book.
- Before reporting glued words (largelydetermine) as a reader bug, look at the raw XHTML: retail EPUBs can carry the typo themselves (0.32.1). Spot-check a surprising figure against a primary file too; a reputable publisher does not rule out a slip.
- A book's claims about research: read the chapter's notes (`--with-next` gets them when they follow), and search the two or three studies carrying the argument for later disputes; a book rarely mentions them (Taking Testing Seriously cites a contested paper as settled).
- Section numbers are not chapter numbers: in a textbook `--section 23` may be chapter 16. Cite the chapter from the `toc` title. A broad textbook usually serves a beat through a few sections: grep the beat's terms across the book first, then read only those (0.32.0).
- Read several sections in one call: `RW read FILE --section 83,87,90-92 --each-chars 4000` caps each section on its own and prints a resume line per cut one (0.31.0). Pictures in their own paragraph show as `[image omitted: t0243-01.jpg]` (a table or formula set as an image: view it if the text leans on it), MathML as `[math: alttext]`; `info` prints authors, date and `isbn` from the OPF.
- EPUB metadata can have title and author swapped; `info` says so in a note (0.21.0). Take the title from the note or the file name, not the `title:` line.
- A Packt-style tutorial: run `toc --code` first (0.34.0; one 867-word section held 92 words of prose), read with `--skip-code --compact` and list only the theory sections; when a printed output backs a claim, read that listing too, and open a cited source before repeating what the book says it found (one book's printed SQL joined unrelated keys, and its cited blog post had run no such test); `--skip-code` also drops the line ending in ':' that introduced each block (0.22.0). A tool output over about 30 KB gets cut off by the harness, so read 4 or 5 sections per call.
- Cite printed pages, not PDF pages: when the page numbers on the pages differ from the PDF's, `info` prints `printed_pages: PDF page + N`. When the offset drifts (a blank page dropped per chapter, as in Palgrave PDFs), `toc` shows each page's own `(p. N)` since 0.28.0 and `read --section p153-p160` reads by printed page; never carry one chapter's offset to another, and give reader agents the `pN` form instead of an offset.
- An image-only EPUB (page pictures, `no text layer`) often has a DjVu twin in the same folder with OCR text: read that first. Else `RW ocr FILE` works on the EPUB too (0.11.0). A DjVu or plain-text book that comes out as one huge section is split at its ALL-CAPS headings automatically; check `RW toc` and expect a few OCR-misread titles.
- A scan can lack whole leaves: since 0.39.0 `info` notes printed-page jumps it finds in OCR text, and they can drop a chapter the contents promises, so compare the contents with the headings you read and name what is absent in the Verdict. Spreads hold two printed pages per section, and a page number glued to a word (`7The`) is the page break, not text: cite the printed number.
- A scanned art or craft book: `RW ocr FILE` first, then `RW grep` for the topic words to find the pages, and read page runs with `--section N-M`. Captions and step numbers come out as short lines; view the page image for a figure the text leans on.
- Endnotes name the studies a chapter rests on. Read the Notes section with `--drop-repeated` (back-links go) and find one chapter's notes with `RW grep FILE "^Chapter 6" --section <notes>` for the offset, then `read --offset`.
- PDF text since 0.10.1 rejoins words hyphenated at line ends (`conven- tions`) and drops running heads with a page number (`4 | Chapter 1: ...`); if a reader still sees them, the PDF uses another pattern: report it. Since 0.10.2 pipe-less heads (`42  Chapter 3: ...`), sentences split by a page break and words split without a hyphen (`tikto ken`) are fixed from the book's own word counts; since 0.11.0 code blocks keep their lines and indentation; tables, definition lists and sidebars in PDFs still come out flattened, so check those against the page (`--section` gives the page numbers).
- A PDF whose bookmarks stop early (a Packt book whose outline ends at the Preface) is split at the chapters of its printed contents page since 0.17.0: `toc` shows `12. 1. Chapter title` lines, read by section number. Titles come from the contents page or the part openers' "Chapter N, Title" lists; if a chapter is missing, it is inside the one before it, so grep its title for the offset. Since 0.18.0 a PDF whose pages carry running heads like `Chapter 2 | Title` is split at the pages where N changes instead (`Chapter 2: Title (p. 27-42)`), and contents dot leaders print as ` … `. Check `RW toc` after a split: a chapter that starts mid-page begins at the top of that page.
- An EPUB whose outline has one entry and whose chapters are bold paragraphs (calibre conversions) used to come out as one giant section. Since 0.30.0 it is cut at the chapters its printed contents page lists one per line (`1 TITLE`), at the paragraph holding just the chapter number when the title follows it, and contents-page lines like `INTRODUCTION` no longer open false sections. `toc` then shows `4. 1. TITLE`; if the giant-section note still shows, grep a chapter title for the offset.
- For a glossary, `RW terms FILE` (0.16.0) lists each headword with the start of its definition, so you pick vocabulary without reading the whole section; `--section N` when the section is not titled Glossary.
- To check one marker, `RW note FILE 39 --section 13` prints the note `[39]` in section 13 points at (0.10.0): numbering restarts per chapter, so give reader agents this instead of the notes section. A notes file the toc skips is titled `Endnotes: Chapter 13`, not `Chapter 13`.
- Typos, hyphens inside words (`priori-ties`) and missing spaces next to an inline symbol are usually in the EPUB itself; check the raw XHTML before calling them a reader bug.

- Brief reader agents with the whole read line: `RW read FILE --section N --compact --out <scratch>/chN.txt`, then their own Read tool on the file. An agent that reads four chapters to stdout overflows its shell output, and one that guesses `--max-chars 3500` samples only each section's opening: one Guerrilla Marketing reader did and had to read again (2026-11-02).
- For a programming book, trust the code over the prose: the Blender scripting book reader found prose naming attributes the code spelled right, and one listing printed without its loop body's indent (in the EPUB's own source). Check API names against the library's current docs before writing them into a skill or notes: versions drift and books lag (2026-11-02).
- For a PDF with no outline, plan from `RW toc FILE --group` and add `--strip-boilerplate` to the reader's read and grep lines (0.14.0): it drops the running head repeated atop every page and the printed page numbers. Give greps `--width 300 --max 8` (or `--count` first): one Epistemic Injustice reader ran 15 greps at full paragraphs and got 35 KB back (2026-11-02).

- Plan from `RW toc FILE --depth 1`: it gives chapter numbers, titles and rolled-up word counts, so you can budget before reading.
- Read the introduction, each chapter summary and any results or comparison sections first (`grep -i "summary|conclusion|results"` with `--count` finds them), and grep the rest for the terms you need.
- Reader agents read a whole chapter in one call with `--max-chars` set above its size (the toc word count x about 6), or `--out FILE` then read the file; the default 25k cap made two agents sample 60-85k-character chapters. Give them a margin: a 9,800-word chapter came to 60,750 characters, just over a 60,000 cap. 
- Over about 150k words, split by part across parallel reader agents. Each returns principles in its own words with a citation and quotes of 25 words or fewer.
- Read a run of sections in one call, batched by chapter, not one section per call: `RW read FILE --section 9-26 --quiet --max-words 400`. Size `--max-words` so sections x words x about 6 characters stays under 25k characters (the `--max-chars` default); each cut line gives the `--offset` to resume. Add `--drop-repeated` when every section carries the same credit or copyright line (image credits ending "All Rights Reserved"): it drops short paragraphs that recur in 30% or more of sections, verbatim or with the same last four words, and says how many went. It is off by default because a book's own templated short lines can match; check the count looks like one line per section.
- A short book (under about 30k tokens in the `toc` header) is read in one pass: `RW read FILE --section A-B --out FILE`, not section by section. For a quote-heavy book add `--drop-epigraphs` (0.19.0: drops each short quotation followed by a dash attribution line, and the line) and cite the author's ideas, not the people quoted.
- Cite by chapter number (`ch. 12`) or a toc section title, not by section number alone.
- Skim a long tutorial chapter with `RW read FILE --section N --headings` before reading it: the subheadings with word counts show which parts matter, then `--at-para P` reads just those.
- In a technical book read the Troubleshooting, Common Issues, Tips and Production sections first: they hold the most practical rules per word. Size sections with `toc`; skip long code walkthroughs or read them with `--skip-code`.
- A long textbook (an IR or ML text of 250k words): give the reader `rank FILE <topic words>` for each topic before any grep, then grep inside the top two sections. EPUB equations are often pictures: since 0.24.0 they print as `[equation 11.32: image]` or `[formula: image]` and subscripts as `k_1`; the values a book gives sit in the prose after the picture, so grep the symbol (`k_1`, `β`) and read the sentences around it (Manning IR, 2026-11-03).
- A math-heavy textbook PDF: equations come out garbled (symbols on their own lines, numbers as `(9.3)` alone); read the prose sections and skip equation-only ones. Since 0.23.0 double-spaced pages are rejoined into paragraphs, glued MATLAB or Python listings are found by `--skip-code`, and tables print as ` | ` rows, still to be checked against the page.
- A textbook PDF from Cengage-style publishers carries a copyright footer on every page and sets math in a symbol font. Since 0.29.0 the footer is dropped by default (`info` notes how many went), outline titles in `toc` give the printed pages (`(p. 165-170, printed 129-134)`), and `info` warns when a Mathematical Pi font is present: `=` then prints as `5`, `+` as `1`, minus as `2`, times as `3`, and fraction bars as underscores. Check every formula against the page image or a second source before writing it into notes. `grep` with an all-lower-case pattern matches any case since 0.29.0 (`--case-sensitive` turns that off).
- A textbook: read only the chapters the purpose needs (its toc parts split micro, macro and appendices cleanly), and each chapter's Conclusion section first; textbook PDFs mix sidebars, figure labels and tables into the prose, so trust prose paragraphs and check numbers against the table they came from.
- Several copies of one book in the folder (early-access EPUBs beside a final PDF): `info` and `toc` each and read the final edition; an early-access contents page says not final and has a different chapter order. A PDF of Python listings: `--skip-code` drops them since 0.26.0, but program output printed as prose stays in.
- A grep over many sections where one section (a code walkthrough, an MCP listing) takes every hit: add `--per-section 2` (0.27.0). EPUB formulas print as `[formula: image]`: tell reader agents to infer them from the prose, and a sentence that stops short (`with 75.`) is usually cut in the EPUB itself.
- Note where the book is dated (library versions, prices, APIs that have since changed).
- A PDF whose toc is one section per page (no outline): read the printed Contents page first (`read --section N` on it) for chapter start pages, then give `read --headings` the whole chapter range at once, not page by page: numbered lists that cross pages (`1 Variable Tempo` ... `10 ...`) only show as a run (0.52.0).
- In EPUBs a note reference prints as `[40]` after the sentence (0.9.3). Brief reader agents that bracketed numbers are note markers, not figures; one agent read "$1.4 billion.40" as a different sum before the brackets.
